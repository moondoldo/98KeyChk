# 98KeyChk 引き継ぎ書

作成日: 2026-08-03

## 現在の目的

Neko Project 21/W上のMS-DOSおよびPC-98実機で動作する、キーボード入力確認プログラムをLSI C-86 Ver.3.30c 試食版で開発する。

キーボード配置の表示、押されているキーの反転表示、通常キーボードとWIN・APPキー付きキーボードの手動切り替えまで実装済みである。今後は実機を含む動作確認と、キーコードや機種差の検証を進める。

## 主要な実装方針

- Git管理する原本は `src/` にUTF-8で配置する。
- `.c` と `.h` はCRLF、MarkdownはLFとする。
- ビルド前に `tools/scripts/convert-src.bat` を実行し、Shift-JISへ変換したファイルを `PC98DEV/SRC/` へコピーする。
- `PC98DEV/SRC/` はGit管理外の生成・ビルド用フォルダーであり、変換済みのCソースを直接編集しない。
- `PC98DEV/` は、Neko Project 21/W内のMS-DOSからHOSTDRV.COMを使って仮想ドライブとして参照する。
- コンパイルはNeko Project 21/W内でLSI C-86を手動実行する。
- 詳細な常設ルールはルートの `AGENTS.md` に従う。

## 98KEYCHK.Cの現在の仕様

- `src/98KEYCHK.C` がプログラム本体である。
- PC-98 BIOSのINT 18h、AH=04hを使い、キーグループ0～15の現在状態を読み取る。
- キーコードの上位側を状態配列の番号、下位3ビットをビット位置として判定する。
- 押されているキーは、テキストVRAMの属性領域 `A200:0000` にある反転属性ビット `0x04` を変更して反転表示する。
- 通常起動ではPC-9801相当の配置を表示し、WINキーとAPPキーは表示しない。
- `/W` または `/w` を付けて起動するとWIN・APP Modeになり、左右WINキーとAPPキーを表示する。
- WIN・APP Modeでは、キーボードへコマンド `0x17` とモード値 `0x03` を送信する。終了時はモード値 `0x00` に戻す。
- 終了操作はCTRL+Cである。キーコード `0x74` と `0x2b` の同時押下を監視する。
- 実行中はCOPYとSTOPの特殊処理を避けるため、INT 05hとINT 06hを一時的にIRETへ差し替え、終了時に元のベクターへ戻す。
- 終了時は反転表示を解除し、DOSのINT 21h、AH=0Ch／AL=06h／DL=FFhでキーボードバッファーを消去する。
- 方向キーは `↑`、`↓`、`←`、`→` で表示する。Shift-JISでは2バイトになるため、反転幅も2桁としている。
- メイン側のRETとテンキー側のRは、どちらもキーコード `0x1c` である。この方式では区別できず、どちらかを押すと両方が反転する。

## キー表示テーブル

`key_displays` は1キー1行で記述し、各要素の末尾に `98KEYBORD.TXT`／`21KEYBORD.TXT` と同じキー名をコメントで記載している。

配列直前のコメントに、各パラメーターの意味を次のように記載している。

```c
/* {キーコード, 表示行(0始まり), 表示開始桁(0始まり), 反転表示する桁数} */
```

この日本語コメントは、ユーザーから明示的に日本語使用の許可を受けて追加したものである。

左右WINキーは、現在次の割り当てとしている。

```c
{0x77, 5,  7, 3}, /* WIN(L) */
{0x78, 5, 32, 3}, /* WIN(R) */
{0x79, 5, 36, 3}, /* APP */
```

Neko Project 21/Wの `keystat.tbl` とソフトウェアキーボードも、`0x77`を左WIN、`0x78`を右WINとしている。一方、`win9x/winkbd.cpp` のWindows仮想キー変換は、`VK_LWIN`を`0x78`、`VK_RWIN`を`0x77`へ変換しており、左右が入れ替わっている。現在の表示と動作は合っているとのユーザー確認があるため、98KEYCHK側は現在の割り当てを維持している。実機での確認時は、この違いに注意する。

## レイアウト資料

- `src/98KEYBORD.TXT` は通常モードの表示見本である。
- `src/21KEYBORD.TXT` はWIN・APP Modeの表示見本である。
- 両ファイルはShift-JISであり、キーボード部分の各行は56バイトに揃えてある。
- `src/98KEYCHK.C` の表示文字列と、両レイアウト資料のキーボード部分は一致させている。
- レイアウトを変更する場合は、資料だけでなく `display_keyboard()` の文字列、`key_displays` の表示位置と反転幅も合わせて確認する。

- `HELLO.C` はLSI C-86でコンパイルし、Neko Project 21/W内のMS-DOSで実行できることをユーザーが確認済みである。
- `98KEYCHK.C` はLSI C-86でコンパイルでき、キー押下の反転表示がおおむね正しく動作することをユーザーが確認済みである。

## 未解決・注意点

- PC-98実機での動作確認は未実施である。
- WIN・APPキーの有無は自動判別せず、通常起動と `/W` の手動切り替えとしている。
- 左右WINキーについて、Neko Project 21/W内でもPC-98側の名称表とWindows入力変換表に違いがある。実機でキーコードを確認できる場合は再検証する。
- RETとテンキー側Rは同じキーコード `0x1c` のため、現在のBIOSキーセンス方式では区別できない。
- `98KEYBORD.TXT` と `21KEYBORD.TXT` はShift-JIS、`98KEYCHK.C` はUTF-8である。文字コードを取り違えないこと。
- `↑`、`↓`、`←`、`→` はShift-JISへ変換可能だが2バイト文字である。表示位置や反転幅を変更する際はバイト単位で確認する。
- `tools/scripts/convert-src.ps1` の入力元と出力先はフルパスである。プロジェクトを移動した場合は、スクリプト冒頭の2変数を変更する。
- 変換スクリプトは出力先だけに存在するファイルを削除しない。原本を削除または改名した場合、古い変換結果は手作業で整理する。
- `PC98DEV/SRC/`、`references/` 内の主要資料、`tools/np21w/` はGit管理外である。`AGENTS.md` のルールに従い、明示的な指示なしに変更・削除しない。
