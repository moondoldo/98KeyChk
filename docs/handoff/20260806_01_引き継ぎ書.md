# 98KeyChk 引き継ぎ書

作成日: 2026-08-06

## 現在の目的

Neko Project 21/W上のMS-DOSおよびPC-98実機で動作する、キーボード入力確認プログラムをLSI C-86 Ver.3.30c 試食版で開発する。

キーボード配置の表示、押されているキーの反転表示、通常キーボードとWIN・APPキー付きキーボードの手動切り替えは実装済みである。実機で判明したキーボード通信、キーバッファー溢れ、機種差への対処を加えながら動作確認を進めている。

## 主要な実装方針

- Git管理する原本は `src/` にUTF-8で配置する。
- `.c` と `.h` はCRLF、MarkdownはLFとする。
- 日本語はコメントと画面表示用の文字列リテラルだけに使用し、Shift_JIS（CP932）へ変換可能な文字とする。
- コメントは原則として日本語で記述する。
- ビルド前に `tools/scripts/convert-src.bat` を実行し、Shift_JISへ変換したファイルを `PC98DEV/SRC/` へコピーする。
- `PC98DEV/SRC/` はGit管理外の生成・ビルド用フォルダーであり、変換済みのCソースを直接編集しない。
- `PC98DEV/` は、Neko Project 21/W内のMS-DOSからHOSTDRV.COMを使って仮想ドライブとして参照する。
- コンパイルはNeko Project 21/W内でLSI C-86を手動実行する。
- C89相当、変数宣言はブロック先頭、`/* */` コメント、Allmanスタイルを使用する。
- 詳細な常設ルールはルートの `AGENTS.md` に従う。

## 98KEYCHK.Cの現在の仕様

- `src/98KEYCHK.C` がプログラム本体である。
- PC-98 BIOSのINT 18h、AH=04hを使い、キーグループ0～15の現在状態を読み取る。
- 押されているキーは、テキストVRAMの属性領域 `A200:0000` にある反転属性ビット `0x04` を変更して反転表示する。
- 通常起動ではPC-9801相当の配置を表示し、WINキーとAPPキーは表示しない。
- `/W` または `/w` を付けて起動するとWIN・APP Modeになり、左右WINキーとAPPキーを表示する。
- 終了操作はCTRL+Cである。キーコード `0x74` と `0x2b` の同時押下を監視する。
- 終了時は全キーの反転表示を解除し、WIN・APP Modeなら通常モードへ戻す。
- 実行中はCOPYとSTOPの特殊処理を避けるため、INT 05hとINT 06hを一時的にIRETへ差し替え、終了時に元のベクターへ戻す。
- 終了時はDOSのINT 21h、AH=0Ch／AL=06h／DL=FFhで、監視中に蓄積したキーボードバッファーを消去する。

## WIN・APPキーの有効化処理

`set_extended_key_mode()` は、実機でWIN・APPキーを認識させるため、PC-98キーボードのデータポート41hとステータス／制御ポート43hを直接使用する。

- 43hへ `0x17` を出力し、キーボードインターフェースの送信を有効にする。
- 41hへ動作モード設定コマンド `0x95` を送り、ACK `0xFA` を確認する。
- 続けてモード値を送り、ACK `0xFA` を確認する。`0x03` はWIN・APPキー有効、`0x00` は通常モードである。
- 最後の送信完了をTxEMPTYで確認する。
- 43hへ `0x16` を出力し、送信を無効にして受信可能な通常状態へ戻し、エラーをリセットする。
- ACKがIRQ1のBIOS処理に先取りされないよう、送受信中だけ `PUSHF` と `CLI` で割り込みを禁止し、`POPF` で処理前のフラグ状態へ戻す。
- TxRDY、RxRDY、TxEMPTYの待機にはタイムアウトを設け、キーボードから応答がない場合に停止し続けないようにしている。

`send_keyboard_byte()` は、RxRDY後に受信した1バイトがACK `0xFA` であることを前提としている。予期しないキーコードを受信した場合に保存して後で渡し直すような複雑な処理は実装していない。

## /W起動時のRET解放待ち

WIN・APP Modeで、起動直後からRETが反転表示されたままになるという報告があった。

現在の推測は、EXE起動に使ったRETの押下コード `0x1C` がBIOSへ処理された後、解放コード `0x9C` が届く前に拡張モード設定を開始し、`send_keyboard_byte()` が解放コードをACKとして読み取って捨てる競合である。キーボードへ送る `0x95`、`0x03`、ACK `0xFA` 自体がRETを押下状態にするわけではない。

対処として、`/W` 指定時は `set_extended_key_mode(0x03)` の直前にBIOSキー状態を読み、RETのキーコード `0x1C` が解放されるまで待つ。これにより、RETの解放をBIOSが処理してから割り込み禁止を伴うキーボード通信へ進む。

キーリピートはRETの押下コードを繰り返すだけなので、待機を誤って抜ける原因にはならない。長時間RETを押し続けると、BEEP抑止前にBIOSキーバッファーへリピート入力が溜まる可能性はあるが、通常の起動操作では問題ないと判断し、現状の処理順を維持している。RET待機にタイムアウトは設けていない。

この対処後に、問題を報告した環境でRET張り付きが解消したかは未確認である。

## キーバッファー溢れBEEPの抑止

実機では、キー状態を監視している間もBIOSキーバッファーへ入力が蓄積し、バッファー溢れのBEEPが鳴る問題があった。

`disable_keyboard_buffer_beep()` はBIOSフラグ `0000:0500h` のD5（`0x20`）を設定してBEEPを抑止する。変更前のD5だけを保存し、終了時に `restore_keyboard_buffer_beep()` で元の状態へ戻す。他のBIOSフラグは変更しない。

## 通常モードの右Shift表示

拡張キーが無効なキーボードでは、左右どちらのShiftを押しても左Shiftのキーコードが届く場合がある。

通常モードの `98KEYBORD.TXT` と `display_keyboard()` では、右Shiftの文字だけを空白にして非表示としている。`key_displays` の右Shift項目 `{0x7d, 4, 32, 5}` は残してあるため、右Shiftのキーコードが届くキーボードでは空白部分が反転表示される。WIN・APP Modeでは右Shiftを表示する。

## 未解決・注意点

- WIN・APPキーの有無は自動判別せず、通常起動と `/W` の手動切り替えとしている。
- 左右WINキーについて、Neko Project 21/W内でもPC-98側の名称表とWindows入力変換表に違いがある。現在の表示と実際の動作は合っているため、98KEYCHK側は `0x77` を左WIN、`0x78` を右WINとしている。
- RETとテンキー側Rは同じキーコード `0x1C` のため、現在のBIOSキーセンス方式では区別できない。
- `/W` 起動直後のRET張り付き対処は競合の推測に基づく。実機や問題報告環境で再現確認する場合は、RETを短く押した場合、画面表示後まで押し続けてから離した場合、通常モードの場合を比較する。
- RET待機中に長時間キーリピートさせると、BEEP抑止前のBIOSキーバッファーが溢れる可能性がある。通常操作では問題ないとして、追加対処は行っていない。
- `98KEYBORD.TXT` と `21KEYBORD.TXT` はShift_JIS、`98KEYCHK.C` はUTF-8である。文字コードを取り違えないこと。
- 日本語コメントと画面表示文字列には、Shift_JIS（CP932）へ変換できない文字を使用しない。
- `tools/scripts/convert-src.ps1` の入力元と出力先はフルパスである。プロジェクトを移動した場合は、スクリプト冒頭の2変数を変更する。
- 変換スクリプトは入力元直下の `.c` と `.h` だけを対象とし、出力先だけに存在するファイルは削除しない。
- `PC98DEV/SRC/`、`references/PC9800_BOOKS/`、`references/NP21W_SRC/`、`tools/np21w/`、`dist/` はGit管理外である。明示的な指示または既存の生成・変換処理を除き、変更・削除しない。
