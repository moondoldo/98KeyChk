# 98KeyChk 引き継ぎ書

作成日: 2026-07-31

## 現在の目的

Neko Project 21/W上のMS-DOSで動作する、PC-98用キーボード入力確認プログラムをLSI C-86 Ver.3.30c 試食版で開発する。

Windows側で編集するUTF-8の原本と、MS-DOS側でコンパイルするShift-JISの変換済みファイルを分離する構成を整備した。次はテスト用ファイルを整理し、プログラム本体の実装へ進む段階である。

## 主要な実装方針

- Git管理する原本は `src/` にUTF-8で配置する。
- `.c` と `.h` はCRLF、MarkdownはLFとする。
- `.c` と `.h` のファイル名および拡張子に含まれる英字は、原本を作成する時点で大文字にする。
- `tools/scripts/convert-src.ps1` で `.c` と `.h` をShift-JISへ変換し、`PC98DEV/SRC/` へコピーする。
- 変換スクリプトはファイル名の大文字化を行わず、入力元のファイル名とサブフォルダー構成を維持する。
- `PC98DEV/SRC/` はGit管理から除外し、変換済みファイルを直接編集しない。
- `PC98DEV/` は、Neko Project 21/W内のMS-DOSからHOSTDRV.COMを使って仮想ドライブとして参照する。
- 詳細な常設ルールはルートの `AGENTS.md` に従う。

## 今日変更した内容

- `tools/scripts/convert-src.ps1` を作成した。
- `tools/scripts/convert-src.bat` からPowerShellの実行ポリシーを恒久変更せずに変換スクリプトを起動できるようにした。
- `tools/scripts/convert-src.md` に変換スクリプトの仕様と実行方法を記載した。
- 変換元と変換先は、スクリプト冒頭のフルパス変数で指定する仕様にした。
- 変換元または変換先のルートフォルダーが存在しない場合は、エラーで停止する仕様にした。
- 入力元以下の `.c` と `.h` を再帰的に処理し、サブフォルダー構成を維持する仕様にした。
- UTF-8を厳密に読み込み、Shift-JISで表現できない文字は `?` に置換せずエラーにする仕様にした。
- 出力の改行コードをCRLFへ統一した。
- 出力は上書きと追加のみとし、出力先だけにあるファイルを自動削除しない仕様にした。
- エラー時は `convert-src.ps1` が内容を表示し、Enterキーが押されるまで待機して終了コード1で終了するようにした。`convert-src.bat` のエラー処理は変更していない。
- ファイル名の大文字化を変換スクリプトへ持たせる案は取りやめ、原本作成時のルールとして `AGENTS.md` に追加した。
- `AGENTS.md` のオーバーエンジニアリング防止ルールを、要件にない極端なケースによる複雑化を避ける表現へ更新した。

## 変換確認結果

- `convert-src.bat` 経由で `convert-src.ps1` が起動することを確認した。
- 日本語を含むUTF-8のCソースがShift-JIS、BOMなし、CRLFで出力されることを確認した。
- Shift-JISで表現できない絵文字がある場合、変換エラーになることを確認した。
- 出力先の既存ファイルと `README.TXT` が削除されないことを確認した。
- 現在のスクリプトにPowerShellの構文エラーがないことを確認した。

アプリケーション本体は未実装のため、LSI C-86でのビルドは実施していない。
