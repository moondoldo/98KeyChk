# PC-98アプリ開発環境

> この文書は過去の開発方針を保管したものであり、現在の作業ルールではありません。

## 目的

Neko Project 21/W上でLSI C-86 Ver.3.30c 試食版を使用し、PC-98のMS-DOS向けアプリケーションを開発する。

Windows側ではCodexを使用してソースコードや設定ファイルを編集する。

## 開発構成

```text
プロジェクト/
├─ AGENTS.md
├─ DEVELOPMENT.md
├─ README.md
├─ .gitattributes
├─ .editorconfig
├─ src/
├─ build/
└─ tools/
   └─ np21w/
```

PC-98エミュレータとしてNeko Project 21/Wを使用する。

エミュレータは次のフォルダーへ配置する。

```text
tools/np21w/
```

Neko Project 21/W内でLSI C-86を実行し、ソースコードをコンパイルする。

CodexはWindows側のプロジェクトファイルを編集する。

## コンパイラ

使用するコンパイラ：

```text
LSI C-86 Ver.3.30c 試食版
```

試食版はSモデルのみを使用する。

大きなコードや大量の静的データを前提にせず、小規模で単純な構成を優先する。

## C言語の記述規則

- C89相当の古いC言語として記述する。
- C99以降の機能は使用しない。
- `//` コメントは使用せず、`/* */` を使用する。
- 変数宣言はブロックの先頭にまとめる。
- `stdint.h` は使用しない。
- `stdbool.h` は使用しない。
- `snprintf` は使用しない。
- `long long` は使用しない。
- PC-98固有処理とDOS汎用処理は、可能な範囲で分離する。
- 過度に防御的なコードは書かない。
- 複数の処理や判断を1行に詰め込まず、読みやすく明示的なコードを優先する。

## 文字コード

Codexが編集するソースコードは、当面は半角英数字のみを使用する。

半角英数字のみであれば、UTF-8とShift-JISの違いを意識せずにLSI C-86へ渡せる。

日本語コメントや日本語文字列が必要になった場合は、文字コード変換方法を別途決める。

EditorConfigの標準仕様にはShift-JISの指定値がないため、`.editorconfig` には `charset = shift_jis` を記述しない。

## 改行コード

次のファイルはCRLFを使用する。

- `.c`
- `.h`
- `.bat`

次のファイルはLFを使用する。

- `.md`
- `.gitattributes`
- `.gitignore`
- `.editorconfig`

## Neko Project 21/W

Neko Project 21/Wは次に配置する。

```text
tools/np21w/
```

`tools/np21w` 内の実行ファイル、DLL、ROM関連ファイルなどは、明示的な指示がない限り変更しない。

エミュレータの設定ファイルは、設定変更が必要な場合のみ編集する。

個人所有のROM、BIOS、MS-DOS入りディスクイメージはGitリポジトリへ追加しない。

## ビルド

現時点では、Neko Project 21/W内でLSI C-86を手動実行してビルドする。

実在しない `Build.ps1` や `BUILD.BAT` を前提にしない。

ビルドスクリプトを追加した場合は、この文書と `AGENTS.md` を更新する。

## 最初に作成するプログラム

最初の題材として、PC-98用のキーボード入力確認プログラムを検討する。

段階的に次の機能を実装する。

1. 文字列を画面へ表示する。
2. DOS標準入力でキー入力を取得する。
3. 入力されたキーコードを表示する。
4. 必要に応じてPC-98 BIOSを使用する。
5. 必要に応じて修飾キーやキーの押下・解放を取得する。
